# 복약·일정 리뷰 확인

- 캘린더 조회는 반복 일정을 저장하므로 쓰기 트랜잭션을 유지합니다. 최대 조회 범위는 92일이며 초과 요청은 일부 결과를 반환하지 않고 400으로 거절합니다.
- 알림 작업은 규칙별 보충 실패를 기록하고 다음 규칙을 계속 처리합니다. 규칙 조회 자체가 실패해도 기존 일정 알림 전달을 시도합니다.
- 보충 대상은 활성 규칙 중 다음 생성일이 조회 상한 이하이며 종료일을 넘지 않은 규칙입니다. 각 규칙의 시간대에서 최종 생성 범위를 다시 계산합니다.
- 종료일 이후까지 이미 생성한 규칙도 미래 복약 취소가 필요하므로 자동으로 `active=false`로 만들지 않습니다. 보충 조회에서 제외하여 불필요한 잠금을 방지합니다. 사용자가 중단한 규칙은 캘린더 조회에서도 잠그지 않습니다.
- 현재 애플리케이션의 patient 하드 삭제 호출은 없습니다. `schedules_patient_fk`는 `patients(id)`를 참조하며 `ON DELETE CASCADE`가 없어 일정이 남은 아이의 하드 삭제를 DB에서 막습니다. 따라서 현재 스키마에서는 삭제로 고아 일정이 생기지 않습니다. 삭제 기능 추가 시 알림 정책과 외래 키 정책을 함께 변경해야 합니다.
- 알림은 앱 내 목록 알림이며 FCM 푸시 발송을 뜻하지 않습니다.
